# **09\_PROMPTS.md**

# **LLM Prompt Design**

**Version:** 1.0

---

# **Purpose**

The CRAG system relies on Large Language Models (LLMs) for intelligent reasoning at multiple stages of the pipeline.

Unlike traditional RAG systems where the LLM is only responsible for answer generation, the CRAG architecture uses specialized prompts for different responsibilities, including retrieval evaluation, knowledge refinement, query rewriting, and final answer generation.

Each prompt is designed with a single responsibility to maximize modularity, maintainability, and interpretability.

---

# **Design Principles**

Every prompt in the system follows these principles:

* Single responsibility  
* Deterministic outputs  
* Structured JSON responses where applicable  
* Low temperature for reasoning tasks  
* No hidden assumptions  
* Easy to debug  
* Easily replaceable

---

# **Prompt Variables**

The following variables are reused across prompts.

| Variable | Description |
| ----- | ----- |
| {question} | User's original question |
| {retrieved\_chunks} | Chunks returned from Qdrant |
| {refined\_context} | Context after refinement |
| {external\_context} | Context obtained from web search |
| {combined\_context} | Final context passed to Generator |
| {query} | Original search query |
| {rewritten\_query} | Search query generated by Query Rewrite |
| {chunk\_text} | Individual chunk content |
| {top\_k} | Number of retrieved chunks |

# **1\. Retriever**

## **Purpose**

Retrieve the Top-K semantically similar chunks from Qdrant.

This node does **not** use an LLM.

Instead, it generates an embedding for the user query and performs semantic similarity search.

---

## **Inputs**

Top K

## **Process**

↓

Embedding

↓

Qdrant Search

↓

Top-K Chunks

        ...

    \]

# **2\. Retrieval Evaluator**

## **Purpose**

Evaluate whether the retrieved chunks sufficiently answer the user's question.

The Evaluator determines which branch of the CRAG pipeline should execute.

---

## **Input Variables**

Question

Retrieved Chunks

---

## **Prompt Template**

You are a retrieval evaluation system.

Your task is to determine whether the retrieved document chunks contain enough relevant information to answer the user's question.

Evaluate the retrieved context based on:

1\. Relevance

2\. Completeness

3\. Accuracy

4\. Sufficiency

Question:

{question}

Retrieved Chunks:

{retrieved\_chunks}

Return your answer ONLY as valid JSON.

{

    "decision":"CORRECT | AMBIGUOUS | INCORRECT",

    "confidence":0.00,

    "reasoning":"..."

}

---

## **Expected Output**

{

    "decision":"AMBIGUOUS",

    "confidence":0.73,

    "reasoning":"The retrieved chunks answer only part of the user's question."

}

# **3\. Knowledge Refinement**

## **Purpose**

Remove irrelevant information from retrieved chunks before passing them to the Generator.

The objective is to improve context quality rather than quantity.

---

## **Input Variables**

Question

Retrieved Chunks

---

## **Prompt Template**

You are a context refinement assistant.

Your task is to extract only the information that directly helps answer the user's question.

Remove:

\- Repeated sentences

\- Irrelevant details

\- Examples unrelated to the question

\- Background information that does not contribute to the answer

Question:

{question}

Retrieved Chunks:

{retrieved\_chunks}

Return only the refined context.

Do not answer the user's question.

---

## **Expected Output**

Multi-head attention allows the transformer to jointly attend to information from different representation subspaces...

# **4\. Query Rewrite**

## **Purpose**

Generate an optimized search query for external knowledge retrieval.

This node executes only when the Evaluator selects the **INCORRECT** branch or when additional external knowledge is required.

---

## **Input Variables**

Question

---

## **Prompt Template**

You are a search query optimization assistant.

Rewrite the user's question into a concise web search query.

Rules

\- Preserve meaning.

\- Remove unnecessary words.

\- Focus on important keywords.

\- Do not answer the question.

Question

{question}

Return ONLY the rewritten query.

---

## **Expected Output**

Transformer multi-head attention explanation

---

# **5\. Knowledge Search**

## **Purpose**

This node does not use an LLM directly.

Instead, it performs external retrieval using the rewritten query.

---

## **Inputs**

# **6\. Generator**

## **Purpose**

Generate the final grounded answer using the available context.

The Generator never answers using its own knowledge when sufficient context has been provided.

---

## **Input Variables**

Question

Combined Context

---

## **Prompt Template**

You are an AI assistant answering questions using only the provided context.

Instructions

\- Use only the supplied context.

\- Do not invent facts.

\- If the answer cannot be found, explicitly state that the information is unavailable.

\- Produce a clear and concise answer.

Question

{question}

Context

{combined\_context}

Generate the final answer.

---

## **Expected Output**

Multi-head attention enables the transformer to attend to different representation subspaces simultaneously. It improves the model's ability to capture relationships between different parts of the input sequence by using multiple attention heads operating in parallel.

# **Error Handling**

Each prompt execution may return one of the following outcomes:

| Status | Description |
| ----- | ----- |
| SUCCESS | Prompt executed successfully |
| FAILED | Model returned an error |
| INVALID\_OUTPUT | Response could not be parsed |
| TIMEOUT | Request exceeded timeout |
| RETRY | Prompt retried automatically |

Prompt failures are captured in the Execution Trace and displayed in the Node Output Inspector.

# **Prompt Logging**

For debugging and visualization, every prompt execution records:

* Prompt text  
* Raw model response  
* Parsed output  
* Token usage  
* Execution time  
* Status

This information is available through the Node Output Inspector but is not shown in the chat interface.

# **Design Philosophy**

Every LLM prompt in the CRAG system performs a single well-defined task rather than acting as a general-purpose assistant. This separation of responsibilities makes the pipeline easier to debug, improves reproducibility, simplifies prompt engineering, and allows individual prompts to evolve independently. By keeping prompts deterministic, modular, and focused, the system becomes more transparent, maintainable, and aligned with the execution visualization presented to the user.
